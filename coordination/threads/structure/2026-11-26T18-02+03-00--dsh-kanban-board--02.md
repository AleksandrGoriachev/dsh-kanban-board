## Что именно сделано

[факт] R7 — в EPIC_TRANSITIONS добавлены четыре перехода by: architect из needs-decision: → agreeing, → decomposed, → accepted, → done. Тупик снят.
[факт] R8 — в sweep() эпик в in-progress переходит в accepted, когда ВСЕ его наряды accepted. Переход идёт через apply (никаких правок карточки в обход), в журнал пишется событие transition с from=in-progress, to=accepted, by=motor, proof «все наряды приняты». Если нарядов ноль — эпик не двигается.
[факт] R9 — тесты: (а) needs-decision → accepted → done; (б) эпик in-progress с двумя нарядами: после приёмки одного статус не меняется, после обоих — accepted и запись в журнале.
[факт] Тесты: node --test test/board.test.mjs test/motor.test.mjs test/api.test.mjs → tests 56, pass 56, fail 0.
[факт] Приёмочная проверка: docs/tasks/0030/checks/epic-lifecycle.mjs → OK epic-lifecycle (поведенческая, на реальных apply/sweep).

[факт] После перезапуска хоста на 0.4.12 эпик f87a4127 из needs-decision закрывается штатно: needs-decision → accepted (архитектор), затем accepted → done (архитектор). Обе строки теперь есть в таблице переходов, панель покажет кнопки.
