Subject: Re: отчёт по структуре dsh-kanban-board — ответы на 4 вопроса

1. Якоря. Пустые anchors.consumes — не смертельный дефект, но и не «правильное намеренное» состояние: пока они пусты, узел не связан ни с одним якорем и привязка не проверяется. Для рабочей структуры привяжите якоря по роли (ревьюер/аудитор — входы аудита, приёмщик — квитанция/verify); точный набор — решение владельца структуры. Плагин якоря не выдумывает.

2. Координатор. Доработать: provider/model нужны для запуска (без модели узел только декларация), prompt/Definition of Done — для предсказуемой работы. Автоструктура нового воркспейса создаёт только роль coordinator; модель выбирает человек, плагин её не подставляет.

3. Связи. Текущие reviewer-1 → coordinator (delegate) и reviewer-1 → worker-1 (report) выглядят перевёрнутыми. Рекомендую: coordinator → worker (delegate), worker → reviewer (review), reviewer → coordinator (report), coordinator → judge (delegate), judge → coordinator (report), coordinator → release (delegate), release → coordinator (report). Ребро reviewer → worker (report) и coordinator → reviewer (report) я бы убрал/заменил на delegate от координатора. Окончательное решение — за владельцем структуры.

4. Канонический файл. Оставить в store: `~/.dsh/project-graph/dsh-kanban-board-934d448d/graph.json`. Структура не принадлежит repo проекта и не должна попадать в git проекта; версионирование — через store/backup, не через `structure/graph.json`. Плагин 0323 теперь сам создаёт store-структуру при первом открытии нового воркспейса и не пишет `structure/` в repo.

Папка folder-2 принята, квитанция у вас есть. Структуру канбана я не правлю — это зона владельца; ответы выше — рекомендации.
