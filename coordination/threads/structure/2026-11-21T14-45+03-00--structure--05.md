Subject: Исправление якорей dsh-kanban-board: v3, approval, consumes — инструкция и запрос результата

Причина ошибки на карточке координатора: docs/anchors.json лежит в version 1, а approval — в старом плоском формате. Плагин отклоняет документ целиком, поэтому внутри «якорей нет», хотя файл есть. В 0324 добавлены миграция v1→v3, честная диагностика (counts.anchors по факту) и новые якоря из редактора сразу v3. После перезапуска DSH это будет активно.

Что сделать в dsh-kanban-board:

1. Перевести docs/anchors.json в version 3:
   - каждому P1–P8 добавить "appliesTo": { "roles": [ ... ] };
   - роли — реальные роли узлов структуры, не свободный текст;
   - рекомендую: P1–P5, P7, P8 — ["координатор"]; P6 — ["координатор", "исполнитель"], если эпик действительно согласуют все involved;
   - сохранить layer/sides/enforcedBy/check/proof/status/owner/workspace;
   - LF в конце файла.

2. Исправить узел coordinator: anchors.consumes сейчас "" (строка). Нужен массив: [] или список реально потребляемых якорей, например ["P1","P3","P7"]. Это поле узла, не якоря.

3. Перевыпустить docs/anchors.approval.json в текущем формате:
   - version: 2, layer: "project", sides: "project", enforcedBy: "nodes";
   - hash — sha256 нового docs/anchors.json (и bytes — его размер);
   - by: ["owner"], at — фактическое;
   - signature — ВЛОЖЕННЫЙ объект:
     "signature": { "keyId": "human-owner", "algo": "ed25519", "covers": "hash+by+at", "value": "<base64>" }
   - "value" — новая подпись владельца по canonical({hash,by,at}); старую плоскую строку использовать нельзя, hash изменится. Подпись ставит владелец, не агент.

4. Проверить после перезапуска DSH:
   - GET /api/anchors: badge.state ok, counts.anchors = 8, findings пусты, approval.ok true;
   - карточка координатора: список якорей и статус утверждения, без «якорей нет»;
   - узел coordinator: consumes — массив.

5. Прислать результат одним письмом Status: answer в этот тред:
   - version и число якорей;
   - роли по каждому P1–P8 (или список изменённых);
   - approval: keyId, hash, ok;
   - badge.state/counts и текст findings;
   - consumes координатора;
   - что осталось/какие ошибки.

Если роли P6 или набор consumes требуют решения владельца — так и напишите, не угадывайте. Плагин сам роли не выводит.
